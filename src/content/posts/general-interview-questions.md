## 一、Linux 系统

### 1. Linux 下 IO 模型有几种，各自的含义是什么

**阻塞 IO**：当一个进程发起 IO 请求时，如果数据未准备好，进程会被阻塞，直至操作完成。

**非阻塞 IO**：发起 IO 请求时进程不会被阻塞，如果数据未准备好，会立即返回一个错误（通常是 EAGAIN 或者 EWOULDBLOCK），告知进程稍后再试。

> 注意：阻塞是文件的特性，不是 read/write 函数的特性。socket、pipe 这类文件是默认阻塞 IO，而普通文件是非阻塞 IO。

**IO 多路复用**：通过使用 select、poll、epoll 等系统调用，单个线程可以监听多个 fd 上的事件，让 OS 内核检测绑定到其（IO 复用函数）上的 fd 读写事件来告诉用户某个 fd 是否可以进行 IO 操作。

**异步 IO**：进程发起 I/O 请求后，可以立即继续执行其他任务，而无需等待 I/O 操作完成。I/O 完成后，系统会通过回调函数或信号等方式通知进程。

**io_uring**：是 Linux 内核中异步 I/O 框架，引入于较新的内核版本。它通过使用环形缓冲区（ring buffers）在用户态和内核态之间高效地提交和完成 I/O 请求。

### 2. epoll 和 poll 有什么区别

使用 epoll_wait 调用完成后，可以直接在 events 参数中拿到所有有事件就绪的 fd，直接处理即可，是一个出参。而 poll 函数的事件集合调用前后大小未改变，只是通过 pollfd 的 event 参数设置我们关心的事件，通过检查 revent 得到就绪的事件。

### 3. 常用命令

- **查看文件最后五行**：`tail filename -n 5`，`tail -f` 实时监控文件，tail -f 原理是检测文件大小
- **输出正在运行的 java 进程**：`ps aux | grep java | grep -v grep`，-v 反向过滤

### 4. 线程切换过程

1. **保存当前运行线程的状态**（上下文），包括寄存器：PC、堆栈指针 SP、通用寄存器；程序状态字：包含 CPU 状态，线程优先级等；内存管理信息：页表指针等
2. **更新线程的状态**为就绪或阻塞，CPU 时间片用完则更新为就绪态，因为等待 IO 则为阻塞态
3. **调度器根据调度算法选择下一个要运行的线程**。常见调度算法：先来先服务、短作业优先、优先级调度、时间片轮转、多级反馈队列
4. **加载新线程的上下文**，将被选中线程的上下文从其存储位置（如内核栈或线程控制块）加载到 CPU 寄存器中
5. **更新内存管理单元 MMU**。如果新线程属于不同进程，可能需要更新 MMU，如页表基地址寄存器
6. **CPU 开始执行新线程的指令**，切换过程结束

### 5. 进程和线程的区别

- 进程是 OS 分配资源的基本单位，而线程是 OS 调度的基本单位
- 进程之间内存和资源（fd）是相互隔离的，而同一个进程内所有线程共享进程的资源
- 进程创建/销毁开销大，需要分配独立的地址空间、资源和 PCB。线程的创建/销毁开销比进程小
- 上下文切换开销，进程大，线程小
- IPC 通信较复杂，通过管道（pipe、fifo）、消息队列、共享内存、信号、本地套接字。线程通信相对简单高效
- 一个进程崩溃后，不会影响其他进程，而一个线程崩溃后可能导致整个进程结束

### 6. 线上 CPU 爆高，如何找到问题所在

- 使用 `top/htop`，按 P 按 CPU 利用率进行排序
- 使用 `strace` 跟踪系统调用：`strace -p <PID>`
- `perf`、vtune、火焰图等工具可以进行更深入的性能分析，找出 CPU 热点函数
- 确认是否存在无限循环或低效的算法
- 确认是否存在锁竞争、死锁等问题，导致线程频繁切换或忙等待

### 7. 进程间通信机制

**pipe（管道）**：
- 优点：实现和使用相对简单，在同一台机器上的进程间传输数据时性能较好
- 缺点：标准管道只能实现单向数据传输；只能用于具有亲缘关系的进程之间；管道的缓冲区有限

**fifo（命名管道）**：可以在没有亲缘关系的任意两个进程之间进行通信，在文件系统中以文件的形式存在

**消息队列**：单条消息的大小受到限制，传输大数据时需要分割处理

**共享内存**：需要额外的同步机制（如信号量、互斥锁）来管理对共享内存的并发访问

**信号**：信号只能传递有限的信息，无法传递复杂的数据；信号可能被忽略或覆盖

**本地套接字**：适用于本地进程间通信

## 二、多线程

### 1. 线程安全

线程安全指多个线程在并发访问共享资源时，不会导致数据不一致或出现竞态条件，程序的执行结果与单线程执行结果相同。

实现线程安全：mutex、cv、rw_lock、atomic、TLS（线程局部存储）

### 2. volatile 的原理

`volatile` 是一个类型修饰符，用于指示编译器该变量可能在程序的任何时刻被意外地修改，**防止编译器对访问该变量的代码进行优化**。确保每次对 `volatile` 变量的访问都发生实际的内存读取或写入。

> 注意：编译器优化会假设程序没有未定义行为，两个线程同时访问同一个数据会产生数据竞争，这是未定义行为。

### 3. 线程的生命周期

新建 → 就绪 → 运行 → 等待/阻塞 → 终止

### 4. sleep 和 wait 的区别

**sleep**：
- 暂停执行：线程在指定的时间内不执行任何操作，进入休眠状态
- 不释放锁：如果在持有互斥锁的情况下调用 `sleep`，锁依然被持有
- 时间控制：基于时间的暂停
- 不可被唤醒：线程只能在指定时间到达后自动恢复执行

**wait**：
- 条件等待：线程在等待某个条件满足后才继续执行
- 释放锁：调用 `wait` 时，线程会自动释放持有的互斥锁
- 可被唤醒：其他线程可以通过 `notify_one` 或 `notify_all` 唤醒等待的线程
- 与互斥锁结合使用

## 三、C++ 基础

### 1. static 关键字

- 修饰全局变量和函数
- 修饰类的成员变量和函数
- 修饰局部变量

### 2. final 关键字

确保子类中重写父类虚函数时函数签名保持一致，也表明这是一个重写函数，增加可读性。

### 3. 虚函数表

- 虚函数表是类级别的，对于同一个类的所有对象，共享同一份虚函数表
- 每个包含虚函数的类的对象只包含一个指向虚函数表的指针（vptr）
- 虚函数多的话，对象所占的内存不会增加（只有一个 vptr 指针）
- 虚函数表通常存储在内存的静态区域中
- 多重继承中，子类对象可能有多个虚函数表

### 4. this 指针

this 指针是类的非静态函数的第一个隐藏参数，类的非静态函数采用的是 this_call 调用类型，this 就是调用对象的地址，通过寄存器传参。

### 5. 析构函数可以抛出异常吗

不建议。如果析构函数本身抛出异常，可能导致：
- **资源泄露**：析构过程可能会中断，导致资源泄露
- **叠加异常**：如果在析构函数中抛出异常，而析构函数正好在异常传播的过程中被调用，会导致"双重异常"，调用 `std::terminate()` 终止程序

### 6. vector 的扩容机制

**为什么是 2 倍**：
- 时间效率：2 倍扩容能保证大部分插入操作的均摊时间复杂度为 O(1)
- 空间效率：2 倍扩容在大多数情况下能较好地平衡空间利用率和扩容频率

### 7. new 和 malloc 的区别

- new 是 C++ 操作符，malloc 是 C 函数
- new 会调用构造函数，malloc 不会
- new 返回具体类型指针，malloc 返回 void*
- new 失败抛异常，malloc 失败返回 NULL

### 8. 为什么栈比堆效率高

**栈**：
- 栈的分配和释放是由编译器自动完成的
- 采用 LIFO 的方式，连续分配在栈空间上
- 仅涉及修改栈指针，时间复杂度为 O(1)

**堆**：
- 堆内存的分配和释放由程序员手动控制
- 涉及复杂的内存管理机制，如查找适合大小的空闲块
- 频繁的分配和释放可能导致堆内存碎片化

### 9. brk 和 mmap 系统调用的区别

**brk**：从堆分配内存，向上移动堆顶指针。free 释放时，并不会将内存还给 OS，而是缓存在 malloc 的内存池中。

**mmap**：在文件映射区分配内存。free 释放时，会将内存还给 OS，内存得到真正的释放。

malloc 时，分配内存大小 > 128 使用 mmap，小于则使用 brk。

### 10. free() 如何知道要释放多大的内存

分配时是内存头 + 内存，返回内存地址。释放时通过该地址往前偏移 16B，读到内存头，内存头中包含了该块内存的大小。

## 四、网络

### 1. TCP 三次握手

1. 客户端发送 SYN 报文
2. 服务器回复 SYN+ACK 报文
3. 客户端发送 ACK 报文

### 2. 为什么断开连接要 4 次

保证数据能够处理完。服务器收到客户端的 FIN 后，可能还有数据需要发送，所以先发送 ACK，等数据发送完再发送 FIN。

### 3. 如果握手只有两次，会出现什么

之前的重复连接初始化可能造成资源浪费。比如一个 client 发起连接，发送 SYN 报文，但由于网络原因迟迟未到达，client 又重新发起了一次连接，而之前的 SYN 报文在新报文之前到达，server 会回复第一个的 SYN 的 ACK+SYN，由于只有两次连接，造成资源的浪费。

### 4. 浏览器打开链接的过程

1. URL 解析，将其拆解为协议、域名和路径
2. DNS 解析，获取 IP 地址
3. 建立 TCP 连接，三次握手
4. 发起 HTTP 请求
5. 服务器处理请求，回复 HTTP response
6. 浏览器接收响应，解析 HTML 并渲染页面
7. 如果启用了 Keep-Alive，复用 TCP 连接

### 5. HTTPS 的加密方式

1. 客户端选择一个随机数，将随机数和自己支持的加密算法发送给服务端
2. 服务端选择一个加密算法和计算一个随机数，加上自己的 CA（证书）发给客户端
3. 客户端验证 CA 的合法性，若合法计算一个 pre-master（随机数），采用 CA 中的公钥加密，发送给服务端。同时通过两个随机数 + pre-master 和加密算法计算出会话秘钥
4. 服务端用自己的私钥解密，得到 pre-master，进而计算出会话秘钥，回复确认之后的通话使用会话秘钥

### 6. 三次握手和 accept 的时序关系

先完成三次握手。
- 半连接队列：还未完成三次握手的连接
- 全连接队列：已经完成三次握手等待调用 accept 的连接

### 7. 给本机 ip 127.0.0.1 发数据会走协议栈吗

会走协议栈，但不会通过物理网卡发送出去，而是在本地进行网络协议的处理和数据传输。数据在发送到 `127.0.0.1`（本地回环地址）时，仍然会经过网络协议栈的各个层级，但操作系统会在处理到链路层时，将数据直接回送给本机。

## 五、架构

### 1. 如何防止请求重复提交

- **设置唯一请求 ID**：每个请求携带一个唯一的标识符（如 UUID），服务器在处理请求前先检查该 ID 是否已被处理过
- **检查请求特征**：通过检查请求的特征（如参数、IP、时间戳等）来判断是否为重复请求

### 2. 如何做到接口的幂等性

幂等：指同一个操作执行多次，产生的效果与执行一次相同。

### 3. 限流策略

**令牌桶算法（Token Bucket）**：
- 令牌桶中按固定速率生成令牌
- 每次请求到来时，需消耗一个令牌
- 允许短时间内的突发流量

**漏桶算法（Leaky Bucket）**：
- 漏桶以固定速率"漏"出请求
- 请求到来时，如果桶中有空余空间，则将请求放入桶中
- 保证请求以固定速率处理，防止瞬时高流量

## 六、MySQL

### 1. 数据库隔离级别

- **串行化**：事务串行执行
- **可重复读**：在一个事务中，同一个查询的结果一致【默认】
- **读提交**：事务可以看到已提交事务的更改
- **读未提交**：事务可以看到未提交事务的更改

### 2. 什么是幻读

同一个事务中两次读取同一个范围，看到了上一次读取时未有的数据。

解决幻读：间隙锁，锁住数据之间的间隙，其他事务不能插入。行 + 间隙 = next-key lock

### 3. MySQL 存储引擎

**MyISAM**：不支持行锁，不支持事务，只支持表级锁，并发度低，只有 binlog 没有 redolog，没有 crash-safe。

**InnoDB**：支持行锁，支持事务，有 redolog。

### 4. 索引失效的场景

- 以 % 开头的 like 查询
- 对索引列进行函数运算
- 对索引列进行数据类型转换
- 正则表达式不会使用索引
- 复合索引的情况下，查询条件不满足最左原则
- 如果 MySQL 估计使用索引比全表扫描更慢，则不使用索引

### 5. 数据库会死锁吗

会。例如：

```sql
# Session1
begin;
select * from t where id = 1 for update; 
select * from t where id = 3 for update;

# Session2
begin;
select * from t where id = 3 for update;
select * from t where id = 1 for update;
```

解决死锁：通过死锁检测，终止掉一些事务。

### 6. 千万级数据分页查询优化

**方案 1**（性能差）：
```sql
select * from table order by id asc limit 90000000, 100
```

**优化方案 2**（如果 ID 是自增且连续的）：
```sql
select * from table where id >= 90000000 limit 100
```

**方案 3**（ID 不连续）：
```sql
select * from table 
where id >= (select id from table order by id asc limit 90000000, 1)
order by id asc limit 100
```

### 7. MySQL 主备复制原理

涉及 3 个线程：
1. 主：binlog 线程——记录下所有改变了数据库数据的语句，放进 master 上的 binlog 中
2. 从：IO 线程——负责从 master 上拉取 binlog 内容，放进自己的 relay log 中
3. 从：SQL 执行线程——执行 relay log 中的语句
