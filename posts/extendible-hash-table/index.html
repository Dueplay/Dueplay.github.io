可扩展哈希表

Categories: Data Structure / Database 2023-10-09

可扩展哈希表是一种动态哈希技术，主要用于解决传统哈希表在数据量增长时需要整体重新哈希的问题。它通过维护一个目录（directory）和多个桶（bucket）来实现动态扩展。

基本概念

全局深度（Global Depth）：目录使用的哈希位数 局部深度（Local Depth）：每个桶使用的哈希位数 目录（Directory）：指向桶的指针数组 桶（Bucket）：存储实际数据的容器

核心思想

可扩展哈希表的核心思想是：

  • 使用目录来间接访问桶
  • 当桶满时，只分裂该桶而不是重新哈希整个表
  • 根据需要动态调整目录大小

插入操作

插入元素时的步骤：

  1. 计算哈希值
  2. 使用全局深度的最低位找到对应的目录项
  3. 通过目录项找到对应的桶
  4. 如果桶未满，直接插入
  5. 如果桶已满：
    • 如果局部深度 < 全局深度：分裂桶，重新分配元素
    • 如果局部深度 = 全局深度：先扩展目录（全局深度+1），再分裂桶

桶分裂

当需要分裂桶时：

  1. 创建新桶
  2. 增加原桶的局部深度
  3. 根据新的局部深度重新分配元素到两个桶
  4. 更新目录指针

目录扩展

当局部深度等于全局深度且桶已满时：

  1. 目录大小翻倍（2^(global_depth) → 2^(global_depth+1)）
  2. 全局深度加1
  3. 复制原有的目录项（每个指针复制两份）
  4. 然后执行桶分裂

删除操作

删除操作相对简单：

  1. 找到对应的桶
  2. 删除元素
  3. 可选：如果桶为空且可以合并，执行合并操作

合并操作

合并条件：

  • 两个桶的局部深度相同
  • 两个桶是分裂关系（buddy buckets）
  • 合并后的元素总数不超过桶容量

查找操作

查找操作非常高效：

  1. 计算哈希值
  2. 使用全局深度的最低位找到目录项
  3. 在对应的桶中查找元素

时间复杂度为 O(1)（平均情况）

优点

  1. 动态扩展：无需预先分配大量空间
  2. 局部操作：只影响部分数据，不需要全表重哈希
  3. 高效查找：O(1) 时间复杂度
  4. 空间利用率：相比线性哈希更好的空间利用

缺点

  1. 目录开销：需要额外的目录空间
  2. 实现复杂：相比简单哈希表更复杂
  3. 指针间接：需要通过目录间接访问

应用场景

可扩展哈希表广泛应用于：

  • 数据库索引：特别是需要动态增长的索引
  • 文件系统：目录结构的组织
  • 缓存系统：需要动态调整大小的缓存
  • 键值存储：如某些 NoSQL 数据库

示例

假设我们有一个桶大小为2的可扩展哈希表：

初始状态：

  • 全局深度 = 1
  • 目录大小 = 2
  • 两个桶，局部深度都为1

插入过程：

插入 5 (hash: 101):
- 看最后1位: 1
- 插入到 bucket[1]

插入 13 (hash: 1101):
- 看最后1位: 1
- bucket[1] 已满，需要分裂
- 全局深度 = 局部深度，先扩展目录
- 全局深度变为2，目录大小变为4
- 分裂 bucket[1]，局部深度变为2
- 根据最后2位重新分配元素

与其他哈希技术的比较

vs 静态哈希：

  • 可扩展哈希表支持动态扩展
  • 静态哈希需要预知数据量

vs 线性哈希：

  • 可扩展哈希表使用目录，线性哈希不需要
  • 可扩展哈希表可能有更好的查找性能
  • 线性哈希空间利用率可能更高

实现要点

在实现可扩展哈希表时需要注意：

  1. 目录管理：正确维护目录和指针关系
  2. 深度跟踪：准确跟踪全局深度和局部深度
  3. 分裂逻辑：正确实现桶分裂和元素重分配
  4. 并发控制：如果需要并发访问，需要适当的锁机制
  5. 内存管理：及时释放不再使用的桶

性能分析

时间复杂度：

  • 查找：O(1) 平均
  • 插入：O(1) 平摊
  • 删除：O(1) 平均

空间复杂度：

  • 数据空间：O(n)
  • 目录空间：O(2^global_depth)

总结

可扩展哈希表是一种优雅的动态哈希技术，通过目录和桶的两层结构实现了高效的动态扩展。它在数据库系统中有广泛应用，是理解动态数据结构的重要案例。虽然实现相对复杂，但其提供的性能优势使其在许多场景下成为理想的选择。
