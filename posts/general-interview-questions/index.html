一. Linux系统

1. Linux下IO模型有几种，各自的含义是什么

阻塞IO：当一个进程发起IO请求时，如果数据未准备好，进程会被阻塞，直至操作完成

非阻塞IO：发起IO请求时进程不会被阻塞，如果数据未准备好，会立即返回一个错误（通常是EAGAIN或者EWOULDBLOCK），告知进程稍后再试

注意：阻塞是文件的特性，不是read/write函数的特性。socket，pipe这类文件是默认阻塞io，而普通文件是非阻塞io

IO多路复用：通过使用select，poll，epoll等系统调用，单个线程可以监听多个fd上的事件，让os内核检测绑定到其（io复用函数）上的fd读写事件来告诉用户某个fd是否可以进行IO操作

异步IO：进程发起I/O请求后，可以立即继续执行其他任务，而无需等待I/O操作完成。I/O完成后，系统会通过回调函数或信号等方式通知进程。

io_uring：是Linux内核中异步I/O框架，引入于较新的内核版本。它通过使用环形缓冲区（ring buffers）在用户态和内核态之间高效地提交和完成I/O请求

2. epoll和poll有什么区别

使用epoll_wait调用完成后，可以直接在events参数中拿到所有有事件就绪的fd，直接处理即可，是一个出参。而poll函数的事件集合调用前后大小未改变，只是通过pollfd的event参数设置我们关心的事件，通过检查revent得到就绪的事件。

6. 进程和线程的区别

进程是os分配资源的基本单位，而线程是os调度的基本单位

进程之间内存和资源(fd)是相互隔离的，而同一个进程内所有线程共享进程的资源

进程创建/销毁开销大，需要分配独立的地址空间，资源和PCB。线程的创建/销毁开销比进程小，因为线程共享进程的地址空间和资源。

上下文切换开销，进程大，线程小。

IPC通信较复杂，通过管道（pipe，fifo），消息队列，共享内存，信号，本地套接字。线程通信相对简单高效，同一进程内的线程共享内存，可以通过共享变量、全局数据结构等方式进行通信，效率更高，但需要注意同步和互斥问题

一个进程崩溃后，不会影响其他进程，而一个线程崩溃后可能导致整个进程结束，一般来说，每个线程都是独立执行的单位，每个线程都有自己的上下文堆栈，一个线程的崩溃不会对其他线程造成影响。但是通常情况下，一个线程崩溃会产生一个进程内的错误，例如在Linux操作系统中，可能会产生一个Segment Fault错误，这个错误会产生一个信号，操作系统默认对这个信号的处理就是结束进程，整个进程都被销毁了，这样的话这个进程中存在的其他线程自然也就不存在了。

9. 进程间通信机制有哪些，各自的优缺点是什么

pipe：优：管道的实现和使用相对简单，适合简单的数据传输需求。在同一台机器上的进程间传输数据时，管道的性能较好。缺点：标准管道只能实现单向数据传输，0读1写，如果需要双向通信，需要创建两个管道；只能用于具有亲缘关系的进程之间，无法在任意两个进程间使用；管道的缓冲区有限，当缓冲区满时，写入操作会被阻塞，影响性能。

fifo命名管道，可以在没有亲缘关系的任意两个进程之间进行通信。FIFO在文件系统中以文件的形式存在。

优：任何进程，只要知道FIFO的路径，都可以进行通信

消息队列：单条消息的大小受到限制，传输大数据时需要分割处理；需要处理消息的发送和接收同步，避免消息丢失或重复处理。

共享内存：需要额外的同步机制（如信号量、互斥锁）来管理对共享内存的并发访问，防止数据竞争和不一致。

信号量

信号：信号只能传递有限的信息（通常是信号编号），无法传递复杂的数据；信号可能被忽略或覆盖，无法保证所有信号都会被接收和处理；

二. 多线程

1. 多线程的几种实现方式，什么是线程安全

线程安全指多个线程在并发访问共享资源时，不会导致数据不一致或出现竞态条件，程序的执行结果与单线程执行结果相同。实现线程安全：mutex，cv，rw_lock, atomic, TLS(线程局部存储)

2. volatile的原理，作用，能代替锁么

volatile是一个类型修饰符，用于指示编译器该变量可能在程序的任何时刻被意外地修改，防止编译器对访问该变量的代码进行优化。确保每次对volatile变量的访问都发生实际的内存读取或写入，避免编译器将其优化为常量或寄存器中的缓存值。

编译器优化会假设程序没有未定义行为，两个线程同时访问同一个数据会产生数据竞争，这是未定义行为。

4. sleep和wait的区别

sleep：

  • 暂停执行：线程在指定的时间内不执行任何操作，进入休眠状态。
  • 不释放锁：如果在持有互斥锁的情况下调用sleep，锁依然被持有。
  • 时间控制：基于时间的暂停，适用于定时任务或延时操作。
  • 不可被唤醒：线程只能在指定时间到达后自动恢复执行，无法通过其他线程的操作唤醒。

wait：

  1. 条件等待：线程在等待某个条件满足后才继续执行。
  2. 释放锁：调用wait时，线程会自动释放持有的互斥锁，进入等待状态。
  3. 可被唤醒：其他线程可以通过notify_one或notify_all唤醒等待的线程。
  4. 与互斥锁结合使用：通常与std::mutex一起使用，确保对共享资源的安全访问。

2. 同步机制的wait和notify

wait在条件不满足的时候释放锁，等待条件改变。另一线程改变了条件后利用notify通知等待该条件的线程。

wait要配合mutex一起使用，且保证释放锁进入等待是一个原子操作。假设不是原子的，在释放锁后还未进入等待前，其他线程得到锁，可以修改条件，进而通知，而当前线程还未进入等待状态，因此会错过这次通知，如果后续没有新的通知，该线程会一直阻塞下去。

2. DNS解析，首先检查本地DNS缓存中是否已经有该域名的ip地址。如果本地缓存没有或者缓存过期，浏览器会向DNS服务器发起请求
3. 得到IP地址后，建立TCP连接，三次握手
4. 发起http请求
   方法 URL 版本\r\n
   请求头\r\n
   \r\n
   请求体\r\n
5. 服务器处理请求，通过\r\n\r\n分割请求头和请求体，然后利用\r\n分割每一行，回复http response
   状态行：包括HTTP版本、状态码（如200、404等）和状态消息（如OK、NotFound等）。例如: HTTP/1.1 200 OK
   响应头（Headers）：包含响应的元数据，如内容类型（Content-Type）、内容长度（Content-Length）和服务器信息（Server）等。

7. 如何避免浏览器缓存

通过设置服务器的 HTTP 响应头来控制缓存行为：
Cache-Control：
Cache-Control: no-cache：告诉浏览器每次都必须向服务器验证是否有新内容，而不直接使用缓存。
Cache-Control: no-store：禁止浏览器和中间缓存保存响应数据，每次请求都会重新获取。
Cache-Control: max-age=0：设置缓存过期时间为 0，浏览器会立即过期此内容并验证更新。
Expires：
Expires: 0：设置缓存过期时间为 0，相当于立即过期。通常搭配 Cache-Control 使用。

8. HTTPS的加密方式是什么，讲讲整个加密解密流程

客户端选择一个随机数，将随机数和自己支持的加密算法发送给服务端
服务端选择一个加密算法和计算一个随机数，加上自己的CA(证书)发给客户端
客户端验证CA的合法性，若合法计算一个pre-master(随机数)，采用CA中的公钥加密，发送给服务端。同时通过两个随机数+pre-master和加密算法计算出会话秘钥
服务端用自己的私钥解密，得到pre-master，进而通过随机数和加密算法计算出会话秘钥，回复一个ACK确认之后的通话使用会话秘钥

3. 如何做限流策略，令牌桶和漏斗算法的使用场景

a. 令牌桶算法（Token Bucket）

原理：

  • 令牌桶中按固定速率生成令牌，存储在桶中。
  • 每次请求到来时，需消耗一个令牌，若桶中有令牌则允许请求，通过；若无令牌，则拒绝或排队。
  • 令牌桶允许短时间内的突发流量，因为桶中可以存储一定数量的令牌。

实现步骤：

  1. 令牌生成：按固定速率（如每秒生成N个令牌）向令牌桶中添加令牌。
  2. 请求处理
    • 请求到来时，检查令牌桶中是否有令牌。
    • 如果有，取出一个令牌，允许请求通过。
    • 如果没有，根据策略（拒绝或排队）处理请求。

b. 漏桶算法（Leaky Bucket）

原理：

  • 漏桶以固定速率”漏”出请求，模拟水从桶中流出。
  • 请求到来时，如果桶中有空余空间，则将请求放入桶中；否则，拒绝请求。
  • 漏桶保证请求以固定速率处理，防止瞬时高流量导致系统过载。

实现步骤：

  1. 请求进入：每个请求尝试放入漏桶。
  2. 请求处理
    • 漏桶以固定速率处理请求，模拟”漏出”。
    • 若桶已满，拒绝新请求。
